01 · Usuarios, grupo y carpeta /srv/proyecto

La consigna exige un usuario por integrante, un grupo llamado proyecto y la carpeta compartida /srv/proyecto. En Debian, abre una cuenta con permisos administrativos y ejecuta:

Debian · administrador
sudo addgroup proyecto
sudo adduser luisa
sudo adduser dario
sudo usermod -aG proyecto luisa
sudo usermod -aG proyecto dario
sudo mkdir -p /srv/proyecto
sudo chown root:proyecto /srv/proyecto
sudo chmod 2775 /srv/proyecto
getent group proyecto
ls -ld /srv/proyecto
id luisa
id dario
date

Adaptación: luisa y dario son nombres de cuenta sugeridos, no nombres impuestos por el profesor. Si ya existen cuentas, no repitas adduser; verifica sus nombres con getent passwd y usa los nombres reales. El modo 2775 activa setgid para heredar el grupo del directorio.

02 · Sudo, chmod y chown

Debe existir una cuenta con sudo y otra sin sudo. En este ejemplo Darío será el usuario administrador y Luisa la cuenta estándar; pueden invertir la asignación, pero debe quedar demostrado cuál es cuál.

# Solo el usuario elegido como administrador
sudo usermod -aG sudo dario

# Verificar pertenencia a grupos
id dario
id luisa

# Crear y asignar un archivo compartido
sudo touch /srv/proyecto/ejemplo.txt
sudo chown dario:proyecto /srv/proyecto/ejemplo.txt
sudo chmod 664 /srv/proyecto/ejemplo.txt
ls -l /srv/proyecto/ejemplo.txt

# Consultar permisos sudo
sudo -l

Cierra sesión y vuelve a entrar para que se actualicen los grupos. Comprueba que el usuario estándar no pertenece a sudo y que no puede ejecutar tareas administrativas. No elimines el único acceso administrativo del sistema.

03 · Firewall: SSH permitido y puerto 8080

La consigna pide permitir SSH, negar el resto de conexiones entrantes y demostrar que el puerto 8080 está cerrado y luego abierto. Configura primero la regla SSH para no perder el acceso remoto.

sudo apt update
sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw enable
sudo ufw status verbose

# Confirmar que no existe una regla 8080
sudo ufw status numbered

# Abrir 8080 temporalmente
sudo ufw allow 8080/tcp
sudo ufw status numbered

Para probar el puerto, inicia en Debian un servicio temporal: python3 -m http.server 8080 --bind 0.0.0.0. Desde Kubuntu prueba curl -I http://192.168.56.20:8080. Antes de añadir la regla, la conexión debe fallar; después de permitirla, debe responder. Al terminar, detén el servidor con Ctrl+C y elimina la regla con sudo ufw delete allow 8080/tcp. Verifica el estado final.

Nota: la dirección 192.168.56.20 corresponde al plan de red documentado en Sprint 1; sustitúyela por la IP real de Debian si cambió.

04 · Acceso SSH mediante llave y actualización

La conexión debe realizarse desde Kubuntu hacia Debian sin solicitar la contraseña de la cuenta remota. Genera la llave en Kubuntu como el usuario que hará la conexión:

# Kubuntu · generar una llave Ed25519
ssh-keygen -t ed25519 -C "grupo1-2026-2"

# Copiar la llave pública al usuario real de Debian
ssh-copy-id dario@192.168.56.20

# Probar autenticación por llave
ssh -o PreferredAuthentications=publickey dario@192.168.56.20

# Debian · revisar permisos de la llave autorizada
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

Si ssh-copy-id no está disponible en Kubuntu, se puede instalar el paquete que lo proporciona o copiar manualmente el contenido de ~/.ssh/id_ed25519.pub al archivo ~/.ssh/authorized_keys del usuario remoto. Nunca publiques ni compartas id_ed25519 (la llave privada).

Después de verificar el acceso por llave, actualiza Debian:

sudo apt update
sudo apt upgrade -y
# Registrar fecha y versión del sistema
date
cat /etc/os-release

Reinicia solo si las actualizaciones lo requieren y vuelve a probar SSH.

05 · Script gráfico Bash en Kubuntu

Debe ser útil, incluir una función, un if, un ciclo y comentarios, y lanzarse desde un ícono del escritorio o menú de aplicaciones. Guarda el archivo como scripts/resumen-sistema.sh:

#!/usr/bin/env bash
# Muestra información básica del equipo gráfico.
set -u

mostrar_resumen() {
  echo "Equipo: $(hostname)"
  echo "Usuario: $(whoami)"
  echo "Fecha: $(date)"
}

mostrar_resumen

# Comprobar herramientas antes de mostrar el almacenamiento.
if command -v df >/dev/null 2>&1; then
  echo "Uso de almacenamiento:"
  for ruta in / /home; do
    if mountpoint -q "$ruta"; then
      df -h "$ruta" | tail -n 1
    fi
  done
else
  echo "No se encontró el comando df"
fi

read -r -p "Presiona Enter para cerrar..."

Habilita la ejecución con chmod +x scripts/resumen-sistema.sh y pruébalo desde una terminal. Crea un lanzador llamado Resumen del sistema.desktop en el escritorio:

[Desktop Entry]
Type=Application
Name=Resumen del sistema
Comment=Consulta información básica del equipo
Exec=konsole -e /bin/bash -lc '/ruta/absoluta/scripts/resumen-sistema.sh'
Icon=utilities-system-monitor
Terminal=false
Categories=System;

Sustituye /ruta/absoluta/ por la ruta real. Da permiso al lanzador con chmod +x y, si KDE lo solicita, marca «Permitir lanzar».

06 · Script de consola con argumento y validaciones

El script debe recibir un argumento, validar la entrada y devolver un código distinto de cero si falla. Guarda como scripts/contar-archivos.sh:

#!/usr/bin/env bash
# Cuenta archivos regulares del directorio recibido.
set -u

if [[ $# -ne 1 ]]; then
  echo "Uso: $0 DIRECTORIO" >&2
  exit 2
fi

ruta=$1
if [[ ! -d "$ruta" ]]; then
  echo "Error: no existe el directorio: $ruta" >&2
  exit 1
fi

if [[ ! -r "$ruta" ]]; then
  echo "Error: no hay permiso de lectura: $ruta" >&2
  exit 3
fi

cantidad=$(find "$ruta" -maxdepth 1 -type f | wc -l)
echo "Directorio: $ruta"
echo "Archivos regulares: $cantidad"
exit 0

Prueba los tres casos y registra el código de salida con echo $? inmediatamente después de cada ejecución:

chmod +x scripts/contar-archivos.sh
./scripts/contar-archivos.sh /srv/proyecto
echo $?
./scripts/contar-archivos.sh /ruta/no-existe
echo $?
./scripts/contar-archivos.sh
echo $?

Resultados esperados: 0 para directorio válido, 1 para directorio inexistente, 2 si falta el argumento y 3 si no hay permiso de lectura.

07 · Procesos: ps, top, kill, nice y renice

Identifica procesos y demuestra los estados solicitados. Los estados son códigos observables en la columna STAT de ps.

EstadoSignificadoDescripción
RRunning / runnableEn ejecución o listo para ejecutarse.
SInterruptible sleepEn espera interrumpible; por ejemplo, sleep.
TStopped / tracedDetenido por una señal o bajo seguimiento.
ZZombieTerminó, pero el proceso padre aún no recogió su estado.
# Listar procesos con PID, estado y prioridad
ps -eo pid,ppid,stat,ni,comm --sort=pid
top

# Crear un proceso de prueba en segundo plano
sleep 300 &
PID=$!
ps -o pid,stat,ni,comm -p "$PID"

# Iniciar otro proceso con prioridad modificada
nice -n 10 sleep 300 &
PID_NICE=$!
ps -o pid,stat,ni,comm -p "$PID_NICE"

# Ajustar prioridad del proceso existente
renice 15 -p "$PID_NICE"
ps -o pid,stat,ni,comm -p "$PID_NICE"

# Terminar solo los procesos de prueba
kill "$PID" "$PID_NICE"
wait "$PID" "$PID_NICE" 2>/dev/null || true
date

Para evidenciar T: ejecuta sleep 300 en primer plano y pulsa Ctrl+Z; consulta su PID con jobs -l y su estado con ps. Reanúdalo o termínalo al finalizar.

Para evidenciar Z: se necesita un proceso padre que no recoja temporalmente el estado de su hijo. No mates procesos del sistema para fabricar el ejemplo. Documenta el procedimiento de laboratorio y captura la salida real de ps si logras observarlo.

El estado R puede ser breve; no todos los procesos se observarán en todos los estados en una única captura. Explica qué muestra el resultado real.

08 · Docker Engine y hello-world

La presentación (página 6) exige Docker Engine instalado y hello-world funcionando. En Debian, una opción sencilla es el paquete de la distribución:

sudo apt update
sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo systemctl status docker --no-pager

# Validar cliente, servidor y contenedor de prueba
sudo docker version
sudo docker run hello-world
sudo docker images
date

La consigna también indica cerrar sesión después de agregarse al grupo docker. Si van a demostrar ejecución sin anteponer sudo, realiza:

sudo usermod -aG docker "$USER"
# Cerrar completamente la sesión y volver a entrar
# Después de iniciar sesión nuevamente:
groups
docker run hello-world

Seguridad: pertenecer al grupo docker concede privilegios equivalentes a root en el host. Añade únicamente la cuenta que necesite administrar contenedores. Si no deseas otorgar ese nivel de privilegio, usa sudo docker ... y explica la decisión al docente; confirma el criterio de demostración con la consigna.

07 / Cierre de avance

Conclusiones del trabajo

Texto base para la reflexión técnica del estado actual. Debe revisarse y complementarse con la experiencia real del equipo.

Conclusión técnica del equipo

El proyecto define una arquitectura de dos máquinas Linux con responsabilidades complementarias: Kubuntu proporciona el entorno gráfico y Debian concentra la administración por consola. El primer sprint establece el montaje, almacenamiento, herramientas y conectividad mediante NAT y Host-only. El segundo sprint amplía esa infraestructura con administración de identidades y permisos, reglas de firewall, autenticación SSH por llave, automatización con Bash, análisis de procesos y Docker. La aceptación técnica depende de ejecutar y registrar cada comprobación en las máquinas reales.

Aprendizajes esperados

El trabajo permite relacionar conceptos fundamentales de sistemas operativos con tareas prácticas: jerarquía de archivos, cuentas y grupos, permisos Unix, filtrado de tráfico, autenticación criptográfica, scripting, planificación de CPU y virtualización de aplicaciones. La documentación reproducible facilita diagnosticar fallos y demostrar el funcionamiento del entorno.

Estas conclusiones son un borrador de apoyo, no una declaración de pruebas realizadas. Añadir experiencias, dificultades y resultados reales individuales antes de entregar.
